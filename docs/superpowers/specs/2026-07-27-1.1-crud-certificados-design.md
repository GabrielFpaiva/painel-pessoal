# 1.1 — CRUD de certificados (design)

Data: 2026-07-27 · Fase 1 · Depende da Fase 0 (fundação) concluída.

## Objetivo

Entregar o CRUD funcional de certificados com arquivo: criar, editar, excluir e
baixar. Upload para o bucket privado `certificates`, download por signed URL de
curta duração, isolamento por RLS verificado com dois usuários.

## Fronteira de escopo

Entra na 1.1:

- Formulário criar/editar com os campos do schema.
- Upload para o bucket privado (teto 5 MB, imagem comprimida no client).
- Download por signed URL curta.
- Exclusão do certificado **e** do arquivo no Storage.
- Lista **enxuta** — só o suficiente para ver, abrir, editar e excluir.

Fica para outra tarefa (não implementar "já que estou aqui"):

- Pré-preenchimento por camada de texto do PDF (`pdf.js`) → **1.2**.
- Grade rica com busca, filtro e tags criadas na hora → **1.3**.
- Banner e badge de vencimento → **1.4**.

## Camada de dados (já existe na migration `20260724000000_init.sql`)

Nada de schema novo nesta tarefa. Já estão prontos:

- Tabela `public.certificates` — `title` (obrigatório), `institution`,
  `issued_on` (date), `expires_on` (date), `workload_hours` (int ≥ 0),
  `credential_id`, `verification_url`, `file_path`, `file_mime`
  (`pdf|png|jpeg`), `file_size_bytes` (≤ 5 MB), `is_public` (default false).
  Check: `expires_on >= issued_on`.
- RLS: `owner_all` (dono faz tudo) e `public_read` (só se `is_public` e perfil
  público).
- Bucket `certificates` — privado, 5 MB, mimes `pdf/png/jpeg`. Policy
  `cert_owner_all` em `storage.objects`: acesso só quando
  `(storage.foldername(name))[1] = auth.uid()::text`, ou seja, pasta por usuário.

Tags (`tags`, `certificate_tags`) existem no schema mas **não** são usadas na
1.1 — pertencem à 1.3.

## Domínio puro — `src/domain/certificates/`

Sem I/O, sem `await`, sem `new Date()` para "agora". Testável no Vitest.

- `file.ts`
  - `validateFile({ mime, size }): { ok: true } | { ok: false; error: 'mime' | 'too_big' }`
    — mime ∈ {`application/pdf`, `image/png`, `image/jpeg`}, `size ≤ 5 * 1024 * 1024`.
  - `extForMime(mime): 'pdf' | 'png' | 'jpg'`.
- `certificate.ts`
  - `validateInput(fields): { ok: true } | { ok: false; error: string; field: string }`
    — `title` não vazio; `workload_hours` ausente ou ≥ 0; se ambos presentes,
    `expires_on >= issued_on`; `verification_url` ausente ou URL bem formada.

Vencimento (janela de ≤ 60 dias / vencido) **não** entra aqui — é 1.4.

## Server Actions — `src/app/(app)/certificados/actions.ts`

Todas retornam objeto `{ error }` tipado; nunca jogam exceção crua na UI.
Todas validam a sessão (client server-side, RLS reforça o dono).

- `createCertificate(input): { id: string; userId: string } | { error }`
  — valida no domínio, insere a linha com arquivo nulo, devolve `id` e `userId`
  para o client montar o caminho `{userId}/{id}.{ext}`.
- `attachFile(id, { path, mime, size }): { ok: true } | { error }`
  — grava `file_path`, `file_mime`, `file_size_bytes`. Confere que a linha é do
  usuário (RLS já garante, mas a action revalida o `id`).
- `updateCertificate(id, input): { ok: true } | { error }`
  — valida no domínio e atualiza o metadado.
- `deleteCertificate(id): { ok: true } | { error }`
  — lê `file_path`; se houver, remove o objeto do Storage pelo client do dono
  (a policy por pasta autoriza); depois deleta a linha. Ordem evita órfão no
  bucket.
- `getDownloadUrl(id): { url: string } | { error }`
  — gera `createSignedUrl(file_path, 60)` (60 s). O client abre a URL.

`revalidatePath('/certificados')` após create/update/delete.

## Upload no client

Componente `CertificateForm` (client component, um só, compartilhado por criar e
editar).

Fluxo ao salvar com arquivo escolhido:

1. Se a imagem, comprime com `browser-image-compression` (alvo ≤ 5 MB, downscale
   sensato). PDF não é comprimido, só validado pelo tamanho.
2. `validateFile` no domínio; se falhar, mostra a mensagem e para.
3. `createCertificate(metadado)` → recebe `{ id, userId }`.
4. Sobe o arquivo para `certificates/{userId}/{id}.{ext}` pelo client do browser
   (a RLS da pasta garante o isolamento).
5. `attachFile(id, { path, mime, size })`.
6. Se o passo 4 ou 5 falhar, o certificado permanece salvo **sem** arquivo e a UI
   avisa: "certificado salvo, mas o arquivo falhou — reenvie". O arquivo é
   opcional por design (o schema deixa `file_path` nulo): dá para cadastrar só
   com metadado + link de verificação.

Nova dependência: `browser-image-compression` (só client, custo zero). Nenhuma
outra biblioteca.

## Testes (fecha o Definition of Done)

- **Vitest (domínio)**: `file.ts` (mime válido/inválido; 5 MB aceito, 6 MB
  recusado; extensão por mime) e `certificate.ts` (título vazio; workload
  negativo; `expires_on` antes de `issued_on`; URL malformada; caso válido).
- **Isolamento de Storage** (novo, no estilo da suíte RLS com dois usuários reais
  locais): A sobe um arquivo em `A/…`; B tenta baixar e listar → negado. Cobre o
  aceite "usuário B não baixa arquivo de A". A suíte RLS de tabelas já cobre
  `certificates` (catálogo) e continua verde — nenhuma tabela nova.
- **Playwright (e2e)**: upload de PDF e de PNG completam; arquivo de 6 MB é
  recusado com mensagem clara; "abrir" gera uma signed URL que responde 200. A
  expiração da URL é assertada pelo TTL (60 s) no unit, não por espera no e2e.
